# OCR wrappers, installed with --no-deps and NEVER listed in requirements.txt.
#
#     pip install --no-deps -r requirements-ocr.txt
#
# They live in their own file because their declared dependencies are wrong
# for this project in two different ways, and because pip resolves the
# metadata of everything in a requirements file whether or not you also
# install it --no-deps somewhere else. Listing them alongside the pins is what
# makes the image fail to build:
#
#   * both declare **opencv-python**, the full build. It installs over
#     opencv-python-headless under the same `cv2` module name, and whichever
#     landed last wins. That is not cosmetic -- measured over six remotes,
#     same numpy, OpenCV 5.0.0.93 against 4.10.0.84 changed *every*
#     fingerprint and six of seven button counts.
#   * rapidocr-onnxruntime 1.3.24 declares **numpy<2.0.0** and
#     rapidocr-openvino 1.4.4 declares a bare **numpy**. Between them they
#     pin the numeric library the entire catalogue was extracted under, in
#     opposite directions.
#
# Neither declaration is a fact about the code: both run correctly under
# numpy 2.2.6 and against the headless OpenCV, which is what the pipeline is
# actually built and measured on.
#
# Their real runtime dependencies are pinned in requirements.txt: numpy,
# opencv-python-headless, openvino, Pillow, pyclipper, PyYAML, Shapely, six,
# tqdm. If either wrapper is upgraded, re-check that list -- --no-deps means
# nothing will tell you when a new one appears, except an ImportError at
# runtime.
rapidocr-onnxruntime==1.3.24
rapidocr-openvino==1.4.4
