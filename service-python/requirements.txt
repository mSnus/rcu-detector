# numpy 2 is safe here and was checked rather than assumed. The 1.26.4 pin
# arrived with the first commit and carried no reason; the only stated
# constraint is rapidocr-onnxruntime 1.3.24's declared `numpy<2.0.0`, which is
# a declaration and not a fact -- it runs fine, and its text output is
# unchanged. Extracting six remotes under 1.26.4 and under 2.2.6, same OpenCV,
# gave **byte-identical fingerprints and byte-identical crops**, and
# verification is ~11% faster (3.27 ms -> 2.91 ms per candidate at 45
# buttons). Retrieval unchanged: recall@1 8/8, separation +0.077.
numpy==2.2.6
scipy==1.13.1
# THE OPENCV VERSION CHANGES EXTRACTION. Do not let it drift, and never let
# the full `opencv-python` build be installed alongside this one -- it shadows
# the headless build and silently swaps the CV library out from under the
# pipeline. Measured on the same six remotes, same numpy, 5.0.0.93 against
# 4.10.0.84: **every fingerprint differed**, six of seven by button count
# (RM-L859-1 47 vs 50, DVD_80 73 vs 75, GINZZU_GM-501_1 lost its only text
# region). That is the query/catalog asymmetry this project keeps finding,
# arriving through the dependency tree instead of through the code.
opencv-python-headless==4.10.0.84
Pillow==10.4.0

# OCR. RapidOCR runs the PP-OCR detection/recognition models under
# onnxruntime: the same model family as PaddleOCR at ~150 MB rather than
# ~1 GB, which is what fits this box. The engine is swappable behind
# app/pipeline/ocr.py -- see OCR_EXTRA in install.sh to add paddle/easyocr/
# doctr/tesseract for engine consensus on a larger machine.
#
# rapidocr-onnxruntime is installed --no-deps by install.sh: its dependency
# list pulls opencv-python (the full build, needs libGL) which shadows the
# headless build pinned above. Its real runtime deps are listed out here.
rapidocr-onnxruntime==1.3.24
onnxruntime==1.23.2

# The same PP-OCR models under OpenVINO. Installed alongside rather than
# instead: it is roughly twice as fast on identical models (see
# RapidOcrOpenvinoEngine for the figures) but it reads *more* text, so it
# changes fingerprints and cannot be adopted on one path only. Having both in
# the image is what allows the two to be A/B'd on the box that matters, which
# is the only place the choice can honestly be made. Selected with
# RCU_OCR_ENGINE=openvino; the default is unchanged.
# Same --no-deps treatment as above, for the same opencv-python clash -- and
# for a second reason found the hard way: rapidocr-openvino 1.4.4 declares a
# bare `numpy`, so a plain install pulls numpy 2.2.6 over the 1.26.4 pinned at
# the top of this file. That silently breaks rapidocr-onnxruntime's own
# constraint and, worse, changes the numeric library the whole catalogue was
# extracted under. Install both wrappers --no-deps; their real runtime deps
# are the ones listed below.
openvino==2024.0.0
# NOT `rapidocr-openvino` -- the wrapper is installed by the Dockerfile and
# install.sh, both with --no-deps, and listing it here instead makes pip
# resolve it *with* deps against the pins above. That is not a warning, it is
# a hard build failure: its bare `numpy` against numpy==2.2.6 and its
# opencv-python against opencv-python-headless is ResolutionImpossible, and
# the image will not build at all.
pyclipper==1.3.0.post6

PyYAML==6.0.2
six==1.16.0
